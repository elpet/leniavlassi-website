# Διαχειριστικό Σύστημα Ραντεβού & Ασθενών

Ασφαλές back-office για το ιατρείο, ώστε η Λένια Βλάσση να διαχειρίζεται τα ραντεβού της και τα βασικά στοιχεία των ασθενών της.

## Τι περιλαμβάνει

- **Είσοδος με κωδικό** (bcrypt hashing, rate limiting στις αποτυχημένες προσπάθειες)
- **Sessions** μέσω ασφαλούς, httpOnly, `SameSite=Strict` cookie, αποθηκευμένα server-side (SQLite session store) ώστε να μπορούν να ανακληθούν
- **CSRF προστασία** (double-submit token) σε κάθε αίτημα που τροποποιεί δεδομένα
- **Κρυπτογράφηση σε επίπεδο εφαρμογής (AES-256-GCM)** για τα ευαίσθητα πεδία ασθενών (τηλέφωνο, email, κλινικές σημειώσεις)
- **Ιστορικό πρόσβασης (audit log)**: κάθε προβολή/δημιουργία/ενημέρωση/διαγραφή/εξαγωγή καταγράφεται
- **Δικαιώματα ΓΚΠΔ του υποκειμένου των δεδομένων**: εξαγωγή πλήρους φακέλου ασθενή σε JSON (άρθρα 15/20) και μόνιμη διαγραφή κατόπιν αιτήματος (άρθρο 17)
- **Καταγεγραμμένη συγκατάθεση** ασθενή πριν την πρώτη καταχώρηση στοιχείων του
- Ασφαλείς HTTP headers (Helmet + αυστηρό Content-Security-Policy), χωρίς CORS (ίδιο origin μόνο)
- **Καρτέλα ασθενή** (`patient.html`): στοιχεία επικοινωνίας, σύνοψη προόδου (μέσος όρος αξιολόγησης, αριθμός συνεδριών) και πλήρες ιστορικό συνεδριών
- **Τυποποιημένες σημειώσεις ανά συνεδρία**: θέμα (λίστα προκαθορισμένων κατηγοριών), κλίμακα διάθεσης 1-5, κλίμακα αξιολόγησης προόδου 1-5, ελεύθερες παρατηρήσεις και πλάνο επόμενων βημάτων — όλα επεξεργάσιμα οποιαδήποτε στιγμή μετά τη δημιουργία τους. Θέμα/παρατηρήσεις/πλάνο κρυπτογραφούνται (AES-256-GCM)· οι αριθμητικές βαθμολογίες (1-5) αποθηκεύονται ως απλοί ακέραιοι.

## Εγκατάσταση (τοπικά/staging)

```bash
cd admin-system
npm install
cp .env.example .env
# Συμπληρώστε στο .env τυχαία SESSION_SECRET και ENCRYPTION_KEY:
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # SESSION_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # ENCRYPTION_KEY

npm run create-admin -- iatreio@example.gr "ΠΟΛΥ-ΙΣΧΥΡΟΣ-ΚΩΔΙΚΟΣ-ΕΔΩ"
npm start
```

Άνοιγμα στο `http://localhost:4000/login.html`.

## ⚠️ Πριν μπουν πραγματικά δεδομένα ασθενών — Checklist Παραγωγής

Ο κώδικας εφαρμόζει τους βασικούς **τεχνικούς** ελέγχους ασφαλείας, αλλά η πλήρης συμμόρφωση με τον ΓΚΠΔ (ειδικά για δεδομένα υγείας, "ειδική κατηγορία" κατά το άρθρο 9) απαιτεί επιπλέον **οργανωτικά και υποδομής** μέτρα που δεν καλύπτονται μόνο με κώδικα:

1. **HTTPS/TLS υποχρεωτικά.** Το σύστημα πρέπει να τρέχει πίσω από reverse proxy (π.χ. Caddy/Nginx) με έγκυρο πιστοποιητικό — ποτέ σε απλό HTTP σε production.
2. **Ασφαλής φιλοξενία.** Χρησιμοποιήστε server/VM ή managed υπηρεσία με περιορισμένη πρόσβαση (firewall, SSH keys, όχι default passwords). Μην τρέχετε σε κοινόχρηστο/δοκιμαστικό περιβάλλον.
3. **Backups.** Τακτικά, κρυπτογραφημένα αντίγραφα ασφαλείας του φακέλου `data/` (SQLite databases), αποθηκευμένα σε ξεχωριστή, ασφαλή τοποθεσία.
4. **Διαχείριση μυστικών.** Το `.env` (SESSION_SECRET, ENCRYPTION_KEY) να μην committάρεται ΠΟΤΕ και ιδανικά να φυλάσσεται σε secrets manager, όχι απλό αρχείο στον server.
5. **DPIA (Εκτίμηση Αντικτύπου).** Καθώς πρόκειται για δεδομένα υγείας, συνιστάται/απαιτείται εκτίμηση αντικτύπου σχετικά με την προστασία δεδομένων πριν τεθεί σε πλήρη χρήση.
6. **Data Processing Agreement.** Αν το σύστημα φιλοξενηθεί από τρίτο πάροχο (cloud hosting κ.λπ.), χρειάζεται υπογεγραμμένη Σύμβαση Επεξεργασίας Δεδομένων (DPA) μαζί του.
7. **Πολιτική διατήρησης & διαγραφής.** Ορίστε πόσο καιρό διατηρούνται τα δεδομένα ασθενών μετά το πέρας της θεραπείας και αυτοματοποιήστε/προγραμματίστε τη διαγραφή τους.
8. **Σχέδιο αντιμετώπισης παραβίασης δεδομένων (breach response).** Ποιος ειδοποιείται, πώς και πότε, σε περίπτωση διαρροής (η Αρχή Προστασίας Δεδομένων εντός 72 ωρών όπου απαιτείται).
9. **2ος παράγοντας ταυτοποίησης (2FA).** Το τρέχον MVP έχει μόνο κωδικό πρόσβασης· για πραγματική χρήση συστήνεται προσθήκη TOTP 2FA.
10. **Ποτέ real δεδομένα ασθενών σε αυτό το git repository.** Η βάση (`data/`) εξαιρείται ήδη μέσω `.gitignore` — μην την προσθέσετε ποτέ χειροκίνητα, ούτε ως backup/export αρχείο.

Μέχρι να καλυφθούν τα παραπάνω, το σύστημα είναι κατάλληλο μόνο για **δοκιμαστική χρήση με πλασματικά (dummy) δεδομένα**.

## Δομή

```
admin-system/
  src/
    server.js          # Express app, middleware, routes
    db.js               # SQLite schema & σύνδεση
    crypto.js            # AES-256-GCM encrypt/decrypt helpers
    audit.js             # Καταγραφή ενεργειών
    middleware/auth.js    # Έλεγχος session
    middleware/csrf.js    # CSRF double-submit token
    routes/               # auth, patients, appointments, audit
  public/                 # Στατικό admin UI (login, dashboard, patients, appointments, audit)
  scripts/create-admin.js  # CLI δημιουργίας/επαναφοράς κωδικού διαχειριστή
```
